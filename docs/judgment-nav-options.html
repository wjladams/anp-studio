Judgments stage — left-nav options

Five ways to organize Judgment configuration like Analysis’s left tree, instead of the current top bar of overlapping toggles and combos. Click a tab to compare layouts. Open this file in any browser.

Closest to Analysis

A — Judgment link catalog

Left tree lists every judgment link that exists. Selecting a leaf opens that editor. Method and view live as secondary choices on the selected link (or as small children under it).

  • Pros: one place to see what needs work; mirrors Analysis tree
  • Cons: long trees on big models; cluster vs node mixed in one list

What moves where

  • Top bar Compare / Wrt / Other / Pairwise|Ratings → left tree
  • Matrix|Questionnaire stays in center chrome
  • Coverage / CR stays as status on leaf or center header
  • Priorities stay right

Task-oriented

B — Mode first (Pairwise / Ratings / Cluster)

Top-level nav is the kind of work, then parents and destinations underneath. Matches how people often think: “I’m doing ratings now.”

  • Pros: clear mental model; ratings never compete with cluster UI
  • Cons: same parent appears under multiple branches; more clicking

What moves where

  • Pairwise | Ratings | Cluster Compare become tree roots
  • Wrt / Other become nested lists under the mode
  • Center only shows the active editor + view toggle

Structure-aligned

C — Parent first, then destination

Navigate by Wrt parent (node or cluster), then pick the destination cluster / comparison set. Method is a child of the destination (or a compact toggle once a dest is selected).

  • Pros: tracks network structure; easy “finish all judgments from Benefits”
  • Cons: method switch is one level deeper than option B

What moves where

  • Wrt combo → expandable parents
  • Other cluster → children of each parent
  • Pairwise/Ratings under each dest (or sticky segment control)

Config dock

D — Left config stack + clean center

Left column is a vertical form of the current controls (Compare, Wrt, Other, Method, Coverage), not a deep tree. Center is only the editor. Same information as today, but ordered top-to-bottom instead of jammed in one horizontal bar.

  • Pros: smallest code change; fixes stacking clutter immediately
  • Cons: less “browse all judgments”; still combo-driven

What moves where

  • Entire JudgmentNavPanel → left column, vertical layout
  • No hierarchy of all links
  • Can evolve later into A/B/C without rewriting the editor

From ia-stage-wireframe

E — Classic wireframe (parent list + session)

Matches docs/ia-stage-wireframe.md: left list of parents that have comparisons; center is Matrix | Questionnaire | (later Graph); right is Session / user context instead of (or above) priorities.

  • Pros: already documented; room for multi-user later
  • Cons: dest/method still need a place (center header or secondary list)

What moves where

  • Left = parents with outgoing judgments only
  • Dest + method in center header (compact)
  • Right = Session ● later; priorities can sit under session or share the right column
