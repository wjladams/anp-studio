Auto-organize clusters

Implementation plan for issue #8: a Structure-tab action that lays out cluster windows from network topology so they do not overlap and inter-cluster links stay readable.

Topology rules. Acyclic graphs use a ranked hierarchy (first → last) with same-rank ties side-by-side. Cyclic graphs use a circular arrangement sized so no two cluster AABBs overlap. Self-loops do not count as cycles.
Goal

What “Organize Clusters” does

One menu / context action recomputes every cluster’s scene (x, y) from the current view network, writes positions through an undoable command, and refreshes the canvas.

  • No two cluster windows overlap.
  • Placement follows topology (hierarchy or circle).
  • Node row order inside a cluster is unchanged.
  • Manual drag remains available afterward.

Tarjan SCCs: DAG of components hierarchical; multi-cluster SCCs on small circles.

Input

Cluster meta-graph

Layout operates on clusters, not individual nodes. Build a directed graph from the current view AnpNetwork:

  • Vertex — each cluster, sized from current row layout (ClusterItem::kWidth × height after layoutNodes()).
  • Edge A → B — at least one node in A has a prioritizer destination in cluster B, and A ≠ B.
  • Weight — count of node→node links (ordering ties / ring order).
  • Ignore self-loops — intra-cluster links already use loop lanes; they must not force circular mode.

Classify

DFS (or equivalent) detects a directed cycle among distinct clusters. No cycle → hierarchical layout. Any cycle → circular layout.

Mode 1

Acyclic hierarchy

Rank clusters with longest-path levels after a topological pass. Sources sit at rank 0; each edge u → v enforces rank(v) ≥ rank(u) + 1. Isolates join rank 0 (or a trailing unconnected band — pick one and keep it consistent).

  • Axis (v1): rank increases left → right (matches LinkItem left/right anchors).
  • Ties: same rank stacked top → bottom with gap G.
  • Between ranks: x[r+1] = x[r] + maxWidth(r) + HGap.
  • Vertical center each column on a shared midline.
Tie order

Within a rank

Deterministic, connection-aware:

  • v1: sort by −weighted degree, then name.
  • Better: barycenter of neighbors in adjacent ranks (1–2 sweeps).

Vertical top→bottom ranking can be a later preference; with today’s link drawer, left→right reads cleaner.

Mode 2

Circular arrangement

When the meta-graph has a directed cycle among distinct clusters, place each cluster center on a circle and size the radius so axis-aligned boxes never overlap.

  • Order: prefer a directed-cycle tour; else −weighted degree, then name.
  • Angle: 2π i / n; optional rotate so heaviest cluster is at top.
  • Position: topLeft = center − (w/2, h/2).
  • n = 1: no-op / center alone. n = 2: horizontal diameter with the same gap rule.
Radius

Non-overlap

Initial estimate from adjacent chord length:

  • chord ≥ max over neighbors of (½diagᵢ + ½diagⱼ + gap)
  • R = chord / (2 · sin(π/n)) for n ≥ 2

Then inflate R (binary search / bump) until all AABB pairs clear — needed when heights differ a lot.

Ship order

Implementation phases

  1. Meta-graph, classify, undo/UI stub Build the edge set (dropping self-loops), detect cycles, wire Network menu + context action to a command that can apply a position map (even if the map is still a temporary cascade).
  2. Acyclic hierarchical layout Longest-path ranks, L→R bands, side-by-side ties, fixed gaps. Covers most sample networks immediately.
  3. Circular layout for cyclic graphs Ring order, radius from chord + AABB verify. Covers ANP feedback and dense meshes.
  4. Polish Barycenter tie order, fit-in-view, persist-on-drag-end, optional vertical axis preference. Optional v2: DAG-of-SCCs hybrid.
