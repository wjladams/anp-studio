Unify Scope chrome

Two options for issue #11 polish: one shared way to pick whose judgments across Judgments, Analysis, and Researcher. Data is already shared (JudgmentSession); these mocks only change presentation.

Current shipping

Split chrome (the problem)

Same session, two UIs: Judgments uses a rich Session panel; Analysis / Researcher use a breadcrumb Scope combo. Names differ; density differs; Judgments has no Scope in the breadcrumb at all.

Goal for A / B

  • One word: always Scope (or always Session)
  • Same primary control shape on every stage
  • Roster manage stays one click away
Today: left = Judgments Session panel  ·  right = Analysis “Network · Scope” breadcrumb. Both change the same document session.

Option A

Breadcrumb Scope on every stage

Promote the Analysis/Researcher pattern to Judgments too. One Scope combo beside Network on all stages. The Judgments right column keeps Priorities and a short “Manage participants…” link — the long Individuals/Aggregates list moves out of the primary chrome (or becomes optional / collapsed).

  • Same control, same label, same place
  • Lowest implementation cost (extend existing combo)
  • Tradeoff: Judgments loses the rich list affordance

  • Judgments + Analysis both show Network · Scope
  • Scope = Alice Chen · Editable chip on Judgments
  • Right rail = priorities + manage only

Why A: one muscle memory — change person in the bar, everywhere. Best if the Session list feels redundant once the combo lists everyone + groups.

Option B

Shared Scope bar + slim Session rail

Keep a dedicated Judgments rail for coverage / quick picks, but rename it to match and mirror the breadcrumb. Every stage gets the same Scope combo in the bar; Judgments adds a slim “Scope” rail that reflects the bar (not a second independent model). Selecting in either place updates both.

  • Consistent naming: always Scope
  • Judgments keeps coverage % and fast list switching
  • Slightly more chrome than A; clearer for heavy multi-user work

On this mock

  • Bar Scope + rail both say Alice
  • Rail header: Scope · Manage…
  • Analysis still bar-only (no rail)
